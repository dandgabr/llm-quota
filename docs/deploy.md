# Deployment (v1)

Status: plan — implemented in [Phase 7](architecture/implementation-plan.md).

## Topology

Docker Compose on a single host, running four units:

```
[ browser ] ──TLS 1.3──▶ [ web ]    (SPA frontend, Vue 3 + Vite)
                ──TLS 1.3──▶ [ api ]   (backend REST API + collectors)
                              │
                              └──▶ [ postgres ]   (dedicated container)
                                       │
                                       └─ backup / PITR
```

- **web** — statically served SPA; talks only to the API over HTTPS.
- **api** — the only unit with DB access; runs the scheduler and connectors.
- **postgres** — dedicated container, on an isolated Docker network; **Postgres
  TLS 1.3-only** (native wire protocol over TCP — no HTTP/3 on this link).

## Required configuration

Secrets are supplied via env, never committed:

- `DATABASE_URL` — `postgres://<user>:<pass>@postgres:5432/llm_quota`
- `LLM_QUOTA_KEK` — base64 32-byte key for envelope encryption
  (`openssl rand -base64 32`)
- `SESSION_SECRET` — server-side session signer
- OIDC credentials when identity providers are connected

See `.env.example` at the repo root.

## Hardening (Phase 7)

- **TLS 1.3 (only)** termination at the ingress (web/api); **HTTP/3 (QUIC)
  preferential** when supported (UDP 443 + ALPN `h3`), with automatic fallback
  `h2 → h1.1`. TLS 1.2 deprecated after a transition window. The ingress/edge
  MUST allow the **QUERY** method (see [ADR-008](architecture/adr/ADR-008-rest-api-tls-quic-query.md)
  and [api-conventions](architecture/api-conventions.md)).
- Postgres accepts TLS 1.3-only (`ssl_min_protocol_version = TLSv1.3`) and the
  app connects with `sslmode=verify-full` + `sslrootcert` (see the DBA skill).
- HTTP security headers: CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`.
- Rate limiting on auth and quota-collection endpoints.
- App-level audit logging (ASVS V16 alignment).

### Certificates

- **Production**: certificate issued by a **real CA** (e.g. Let's Encrypt via
  ACME) with automatic renewal. Never use local/self-signed certificates in
  production.
- **Local development/testing only**: a self-signed certificate generated by
  `scripts/cert-local.sh` into `certs/`, which is **git-ignored and never
  committed**. `NODE_ENV=production` refuses to load `local.*` certs. See
  [api-conventions](architecture/api-conventions.md) and `scripts/cert-local.sh`.

## Backup & PITR

- Scheduled logical dump (e.g. daily `pg_dump`) and WAL archive for
  point-in-time recovery.
- Backups stored off-host and restore-tested in the runbook.

## Observability

- Structured application logging.
- Metrics for collector runs, FX cache hits, and endpoint latency
  (Phase 7 scope).
